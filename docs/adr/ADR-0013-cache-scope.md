# ADR-0013 · 缓存命中不做 workflow 作用域隔离（P2-06 裁决）

日期：2026-11-05 · 状态：已裁决 · 关联：专家账本 P2-06、P1-02/03/04（缓存键）、B9 的 `_cache_hit_is_material`

## 背景

专家账本 P2-06：缓存命中查询（`runengine.execute_node` 的同键成功 NodeRun）没有
`workflow_id` 过滤，**任何项目**的同键成功结果都会被复用，担心"跨项目串味"。

## 裁决

**维持现状：缓存键是内容寻址的，不做 workflow 作用域隔离。** 理由：

1. **键里已经没有"身份"可言。** 缓存键 = sha256(EXECUTOR_VERSION | params | inputs.artifactSha
   | caps | doc_sha)（规格 §5.3）。两个 Run 键相同 ⇔ 输入内容逐字节相同、执行器版本相同、
   caps 集合相同、文档快照相同——产出必然逐字节可互换。加 workflow 作用域只会把
   "内容相同却要重算"变成默认，破坏增量的全部价值（40s 片 9.69% 重渲、B8 验收
   43–44s 二次 Run 都建立在跨 Run 命中上）。
2. **"串味"的真实风险不是作用域，是"文件还在不在"。** 跨项目命中只登记产出项目的
   内容寻址路径；B9 已修"命中必须文件还在"（`_cache_hit_is_material`：候选按 id 倒序
   取第一个产物文件真实存在的），并实测过删项目导致 C02 字体产物悬空 → C03 失败
   的场景。2026-11-05 的 FrameServer token（P2-32）再把"复用别的进程的帧服务"这条路
   fail-closed 掉。
3. **残留风险与监测点。** 理论残余：某执行器输出依赖"项目身份"而不在键里（例如
   params 里塞了未声明输入）。守卫是一键复核第 3 项（外部指纹入键：A01/A03/F01/G01、
   G02/G04 项目输入、C01 引擎包）+ 单测 `test_cache_inputs.py`。新增执行器时把
   项目身份类输入补进 `_cache_params_for_node` 是准入检查项（AGENTS.md 门禁清单）。

## 结论

- 不改代码。
- `params_snapshot`/节点 params 的"隐式项目身份"是新执行器的 code review 项。
- 若未来出现"同内容不同项目必须产出不同结果"的需求（如按项目水印），必须把该
  输入显式进键，而不是加作用域。
